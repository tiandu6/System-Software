与本任务直接相关的实际类型如下：

```c
struct Page {
    int ref;
    uint64_t flags;
    unsigned int property;
    list_entry_t page_link;
};

typedef struct {
    list_entry_t free_list;
    unsigned int nr_free;
} free_area_t;

struct pmm_manager {
    const char *name;
    void (*init)(void);
    void (*init_memmap)(struct Page *base, size_t n);
    struct Page *(*alloc_pages)(size_t n);
    void (*free_pages)(struct Page *base, size_t n);
    size_t (*nr_free_pages)(void);
    void (*check)(void);
};
```

**页面及地址约定**：

- `PGSIZE = 4096`，`PGSHIFT = 12`。每个 `Page` 描述符对应一个物理页；同一 `pages[]` 数组中相邻描述符对应相邻物理页，`base + n` 是向后移动 n 个描述符，不是地址加 n 字节。
- 只有空闲块首页的 `property` 记录块的页数，只有空闲块首页设置 `PageProperty` 并挂入空闲链表；块内部其他页不单独入链。
- `nr_free` 表示总空闲页数，不是空闲块数。分配返回页描述符，不返回原始物理地址。
- `PageReserved(p)` 表示保留页；`PageProperty(p)` 表示空闲块首页。可用 `SetPageProperty`、`ClearPageProperty`、`set_page_ref`、`page_ref`、`assert`。
- 链表可用 `list_init`、`list_empty`、`list_next`、`list_prev`、`list_add_before`、`list_add`、`list_del` 和 `le2page(le, page_link)`。`list_add` 在指定节点之后插入；`list_add_before` 在之前插入。
- 原有测试直接访问当前文件中的 `free_list` 与 `nr_free`，并且会临时保存/替换这些状态；实现须提供这两个名称，状态不能另存为测试不可见的副本。可仿照参考文件使用一个 static `free_area_t` 配合宏。

## 全局状态约束

- 空闲链表按物理页地址递增，每个空闲块恰有一个首页节点；块之间不重叠。
- 合法登记、分配和释放后，`nr_free` 等于各空闲块长度之和；测试临时替换链表的中间步骤以其自身约定为准，不额外强制跨步骤一致性。
- 登记或释放时合并相邻空闲块，使连续空闲范围不被无必要地分成多个节点。
- 页面管理信息的初始化不等于清空物理页的数据内容；本任务不要求擦除页面数据。
- 现有单核实验环境由调用方保证操作串行；不引入新的锁、动态堆分配或并发机制。

## best_fit_init

**Pre-Condition**：
- 在向此分配器交付物理页之前调用。

**Post-Condition**：
- 空闲链表成为合法空循环双向链表，总空闲页数为 0；可以开始登记空闲范围。

## best_fit_init_memmap

**Pre-Condition**：
- 管理器已初始化；`n > 0`；`base` 指向同一有效描述符数组中连续 n 页的起点。
- 这些页仍处于保留状态，且没有被本分配器登记、分配或与已有空闲区重叠。

**Post-Condition**：
- 这 n 页成为可分配页面，引用计数清零，总空闲页数恰好增加 n。
- 空闲链表仍有序、无重复节点；本范围与相邻空闲范围在连续时合并。

**Case 1**：
- 原链表为空时，登记为唯一空闲块，首页记录正确长度。

**Case 2**：
- 已有空闲块时，将范围登记到正确位置；不连续则保持独立，向前、向后或两侧连续则合并为一个块。

**Requirements**：
- 保留页检查失败或 `n=0` 属于调用约定错误，使用框架断言报告，不静默把保留的系统区域变为可分配页。

## best_fit_alloc_pages

**Pre-Condition**：
- 管理器已初始化，`n > 0`。

**Post-Condition**：
- 成功时恰好分配连续 n 页，返回首页描述符，分配范围不再作为空闲块出现，总空闲页数减少 n。
- 在所有能容纳 n 页的空闲块中选择长度最小者；长度相同时选择地址较低者。
- 失败时返回 `NULL`，空闲链表、块长度、标志和总空闲页数不变。

**Case 1**：
- 空链表、总空闲页不足，或总数足够但没有足够大的单个连续块时，返回 `NULL`。

**Case 2**：
- 最优块恰好为 n 页时，整块分配并移除对应空闲节点。

**Case 3**：
- 最优块大于 n 页时，从其低地址端分配 n 页，剩余部分成为有正确首页、长度和链表位置的空闲块。

**Requirements**：
- 不能在遇到第一个足够大的块时无条件结束查找；但找到恰好匹配的块后可以结束，因为不存在更小的合法候选。
- `n=0` 用断言拒绝，不产生零长度分配。

## best_fit_free_pages

**Pre-Condition**：
- `n > 0`；`base` 到 `base+n` 表示合法、连续、已分配且非保留的 n 页，不与已有空闲块重叠。
- 调用方保证没有使用中的引用，不重复释放。

**Post-Condition**：
- 本范围重新可分配，引用计数清零，总空闲页数恰好增加 n。
- 相邻空闲块合并，链表有序；只保留最终合并块首页的空闲块标志和节点。
- 合并只改变块组织方式，不重复增加总空闲页数。

**Case 1**：
- 与左右空闲块均不相邻时，插入为独立空闲块。

**Case 2**：
- 只与左侧或右侧空闲块相邻时，合并对应一侧，正确更新首页和长度。

**Case 3**：
- 同时与两侧相邻时，三个块合并为一个块，最终首页位于最低地址，两个旧边界不再作为独立节点。

**Requirements**：
- 链表相邻不等于物理页连续，合并必须依据页面范围相接。
- 不修改已经分配出去的相邻页，也不触碰原有测试函数。

## best_fit_nr_free_pages

**Pre-Condition**：
- 管理器已初始化。

**Post-Condition**：
- 返回当前总空闲页数，不改变任何页面或链表状态。

   分别验证分配优先级；只检查所属 slab，不要求槽位地址顺序。
8. 释放所有对象，验证 empty 保留上限，
   多余空 slab 已归还后端。

同时验证：
小对象数量明显大于后端申请页数，
排除“每对象申请一页”的错误实现。

五、验证存活数据不被破坏
涉及 slub_test_data_integrity。

1. 同时保存多个尺寸类及多个 slab 的存活对象。
2. 按对象编号和字节偏移生成可重复内容模式，
   写入恰好请求长度的区域。
3. 释放其中一部分对象，执行其他分配、释放和回收。
4. 检查所有未释放对象的请求区间内容保持不变。
5. 覆盖对象首字节、尾字节及完整请求区间。
6. 不写请求长度之外的字节，也不读取已释放对象。
7. 断言生产实现没有把存活对象的有效载荷继续用于 freelist。

六、验证大对象及跨页布局
涉及 slub_test_large_alloc。

1. 覆盖 2049、PGSIZE-1、PGSIZE、PGSIZE+1、
   2*PGSIZE+17 等请求。
2. 根据实际大对象头部及对齐偏移，
   独立计算期望后端页数。
3. 补充“头部+有效载荷”恰好落在页边界及前后一字节的场景。
4. 断言：
   - 后端页数包含头部和填充；
   - 返回指针满足对齐；
   - 请求区间完全位于后端分配内；
   - 记录的首页和页数与真实后端调用一致。
5. 对跨页数据写入模式，执行其他分配后复查。
6. 仅调用 kfree(ptr) 即可归还整段后端内存，
   归还页数正确且只释放一次。
7. 多个大对象交错释放时，剩余对象内容保持有效。

七、验证失败及回滚
涉及 slub_test_failure。

1. 使用确定性后端失败注入，覆盖：
   - 无可用 slab 时，新建 slab 的页申请失败；
   - 全部已有 slab 已满，扩容失败；
   - 大对象页申请失败。
2. 失败返回 NULL，不遗留空壳 slab、虚假已用数或后端页泄漏。
3. 已有对象内容及归属保持不变。
4. 关闭故障注入后，相同正常请求能够重新执行。
5. 有现成空闲槽位时，即使后端被设置为失败，
   小对象分配仍应成功，且后端申请次数不增加。
6. 以 size_t 上限及其附近值覆盖：
   头部相加、对齐、页数计算和后端能力上限。
   断言不能回绕成小请求、越界访问或死循环。
7. 明显算术非法的请求在调用后端前返回 NULL。
8. 如果实现存在取得资源后的可失败步骤，
   对其逐项注入失败并检查回滚；
   若没有该类步骤，应说明，无需人为添加。
9. 重复释放、内部指针释放等非法输入不混入正常测试。
   如增加断言测试，使用独立负向入口，明确预期失败方式。

八、验证回收与页面守恒
涉及 slub_test_reclaim。

1. 让不同尺寸类各保留空 slab，记录待回收集合。
2. 调用 slub_reclaim()：
   - 返回值等于实际归还的页数；
   - nr_free_pages() 增量与返回值相等；
   - 对应链表和活动引用已清理。
3. 保留部分存活对象后执行回收：
   含存活对象的 slab 和大对象不能被释放，内容保持有效。
4. 无新增可回收对象时再次调用，返回零。
5. 所有测试分配释放并回收后：
   后端空闲页数恢复基线，后端记录中无未释放测试分配。
6. 比较的是完整清理前后基线；
   不错误要求每次 kfree 小对象都立即增加底层空闲页数。

九、验证确定性混合操作序列
涉及 slub_test_sequences。

1. 使用固定种子生成混合操作：
   不同大小分配、随机选择存活对象释放、间歇回收。
2. 大小分布包含尺寸类边界、非二次幂及跨页大对象。
3. 逐步维护存活对象表，每步检查：
   - 对齐和请求区间无重叠；
   - 内容模式；
   - 结构不变量；
   - 后端资源归属和计数。
4. 分配失败时不加入存活表，继续验证既有对象。
5. 序列结束释放全部对象并回收，检查页面守恒。
6. 失败日志包含种子、步骤号、操作、请求长度和相关指针，
   能据此稳定复现。

十、完成内核验证并报告证据
涉及 slub_check 和测试入口。

1. 至少通过真实 Buddy 后端完成一次完整内核自检；
   受控后端测试不能替代实际接入验证。
2. 保留原有 Buddy 检查。
3. 资源条件满足时，连续执行两次 SLUB 自检，
   两次均恢复各自基线。
4. 仅在必需断言全部通过且清理完成后输出：
   slub_check() succeeded!
5. 不修改生产算法来规避失败，不删除失败断言，
   不提前打印成功。

最终报告：
- 列出需求、夹具、操作和断言的对应关系；
- 区分真实内核测试、受控后端测试及负向测试；
- 给出实际命令、退出状态和关键日志；
- 区分通过、失败、未运行；
- 发现缺陷时给出最小复现及预期/实际差异；
- 不把编译通过当作算法验证通过。
