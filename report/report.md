## 一、实验目的

本实验的总体目的是在 RISC-V 架构上实现并理解 uCore 内核线程从创建到首次运行的完整过程，掌握页表管理、线程创建、中断控制和上下文切换如何配合，使 CPU 能够从启动时的 `idleproc` 切换到新建的 `initproc`。具体目标包括：

1. **掌握页映射的建立、更新和撤销。** 通过实现 `page_insert()` 和 `page_remove()`，理解页表项、物理页引用计数与 TLB 之间的关系，掌握同页权限更新、异页替换、重复删除和分配失败回滚的处理方法。
2. **理解内核线程的创建与首次运行。** 通过初始化进程控制块、分配内核栈、登记 PID 和构造初始执行现场，理解 `idleproc` 如何复用启动现场，以及新建的 `initproc` 如何借助 `context` 和 `trapframe`，从第一次被调度进入 `init_main()`。
3. **掌握线程调度与上下文切换。** 通过实现 `schedule()`、`proc_run()` 和 `switch_to()`，理解内核如何选择可运行线程、按需切换页表、保存和恢复寄存器。结合 `local_intr_save()` 和 `local_intr_restore()`，理解调度临界区为何需要暂时关闭本地中断，以及嵌套调用为何必须恢复进入前的中断状态。
4. **理解多级页表的共性与接口设计。** 对比 Sv32、Sv39 和 Sv48 的页表层数与索引方式，解释 `get_pte()` 为什么在不同层级重复相似的查表步骤，并从代码复用、查询副作用和失败回滚三个角度，分析将页表查找与页表页分配合并或拆分的取舍。

## 三、实验整体逻辑分析

### 3.1 本章节的逻辑主线

本章围绕“发生中断或异常后，内核如何接管执行并正确返回”展开。在前面实验能够启动内核和管理物理内存的基础上，本实验补上 Trap 的上下文管理和具体事件处理，使内核能够响应突发事件，而不是只按原来的指令顺序一直运行。

整个过程分为硬件记录、汇编保存恢复和 C 语言处理三个环节。硬件先记录 Trap 原因、返回位置和相关状态，并进入 `stvec` 指定的入口；`trapentry.S` 再把通用寄存器和相关 CSR 快照保存在当前栈上；`trap.c` 根据原因分发到中断或异常处理函数。处理结束后，从同一份 Trap frame 恢复状态，通过 `sret` 返回。

主要执行关系为：

```text
kern_init() 完成启动准备，idt_init() 设置 Trap 入口
    ↓
clock_init() 设置首次时钟事件，intr_enable() 开启中断
    ↓
发生交给 S 模式处理的中断或异常
    ↓
硬件记录返回位置、原因和状态，跳到 __alltraps
    ↓
SAVE_ALL：保存现场，sp 指向当前 Trap frame
    ↓
通过 a0 传递帧地址，调用 trap(tf)
    ↓
trap_dispatch(tf) 判断类型
    ├─ interrupt_handler(tf)：处理中断
    │      └─ 时钟事件重设、计数、周期输出及规定条件下关机
    └─ exception_handler(tf)：处理异常
           └─ 非法指令、断点及兜底处理，按要求更新 epc
    ↓
处理函数返回，继续进入 __trapret
    ↓
RESTORE_ALL 恢复现场，sret 返回指定执行位置
```

时钟中断是异步事件，处理后通常继续执行被打断的代码；非法指令和断点是当前指令引起的同步异常，按本实验要求处理后要调整 `epc`，避免再次执行同一条异常指令。两者共用入口和现场管理机制，但具体处理行为不同。

### 3.2 功能的逐步实现

**1. 复用内存管理基础，准备 Trap 处理入口。**

将 Lab2 完成的物理内存初始化和 Best-Fit 实现迁入对应位置，保留 Lab3 新增的中断保护包装。`idt_init()` 设置 `sscratch` 的初始状态，并将 `__alltraps` 的地址写入 `stvec`。这里虽然沿用 IDT 的命名，实际是配置 RISC-V 的统一 Trap 入口，不是建立 x86 的中断描述符表。

**2. 按已有保存关系实现上下文恢复。**

先核对 `SAVE_ALL` 与 `struct trapframe`，确认 RV64 下帧大小为 288 字节，旧 `sp` 位于第 2 号槽位。恢复时取出帧内的返回状态，恢复通用寄存器，最后恢复 `sp`，保证整个读取过程中帧基址有效。这个环节是处理结束后能够继续运行的基础。

**3. 建立汇编入口与 C 函数之间的调用关系。**

保存完成后，通过 `a0` 将当前帧地址传给 `trap(struct trapframe *tf)`。C 函数访问的是汇编已经保存的同一份上下文，不是再建立一个副本。C 返回时保持调用前的栈指针，使程序能够继续进入 `__trapret`。

**4. 完成中断和异常的具体处理。**

`trap_dispatch()` 根据原因区分中断和异常。时钟中断每次都设置下一次事件，并维护 `ticks`、按规定输出统计信息和关机；非法指令和断点异常输出相应信息，结合实际指令长度调整 `tf->epc`。未要求恢复的其他异常通过输出 Trap frame 辅助诊断。这样既能识别事件，也能与后续返回路径衔接。

**5. 将上下文管理与事件处理集成验证。**

上下文恢复决定寄存器和执行位置能否正确恢复，具体处理函数决定事件如何处理以及是否需要改变返回位置，两者必须一起配合。验证时先检查编译和各模块行为，再通过 `make qemu` 观察内核输出，通过 `make grade` 检查课程用例；编译运行和评分截图统一放在第五部分。

### 功能模块一：虚拟内存页操作功能

**负责人：2511592-陈逍宇** 

#### 模块功能描述

**需要实现/修改的汇编接口：**

```c
int page_insert(pde_t *pgdir, struct Page *page, uintptr_t la, uint32_t perm);(kern/mm/pmm.c)
void page_remove(pde_t *pgdir, uintptr_t la);(kern/mm/pmm.c)
```

**与之衔接的已有接口：**

```c
get_pte()、pte_create()、pte2page()、page_ref_inc()、page_ref_dec()、set_page_ref()、alloc_page()、free_page()、tlb_invalidate()、flush_tlb()   
pde_t、pte_t、struct Page、pages、boot_pgdir_va  
PTE_V、PTE_U、PTE_W、PTE_R
```

**功能说明：**

这个模块负责在现有多级页表框架上完成最基本的映射维护，也就是把物理页挂到指定线性地址上，以及把已有映射安全地撤销掉。

#### 关键状态和实现步骤
##### 关键状态

`page_insert()` 和 `page_remove()` 都会改变线性地址 `la` 的映射。实现时需要同时维护三项状态。

| 状态 | 在代码中的含义 | 更新要求 |
|---|---|---|
| 末级页表项 `*ptep` | `PTE_V` 表示该项有效，物理页号和权限位决定 `la` 指向哪一页、允许怎样访问 | 建立或替换映射时写入新页号和权限，删除时清零 |
| 物理页引用计数 `page_ref(page)` | 记录物理页持有的引用；每个有效映射贡献一个引用 | 新增映射加一，撤销映射减一。同一地址重新映射到同一页时计数不变 |
| TLB 中缓存的地址翻译 | CPU 可能仍缓存 `la` 对应的旧物理页或旧权限 | 先更新页表项，再使对应翻译失效，最后才允许回收旧页 |

##### `page_insert()` 的实现步骤

1. **取得末级页表项。** 先保存 `pgdir[PDX1(la)]` 的原值，再调用 `get_pte(pgdir, la, 1)`。参数 `1` 允许创建缺失的中间页表。若第一次分配成功、第二次失败，根表项已经发生变化，因此要恢复原值、刷新 TLB 并回收刚分配的页表页，然后返回 `-E_NO_MEM`。此时目标物理页的引用计数仍保持原值。
2. **判断原映射。** 若 `*ptep` 带有 `PTE_V`，用 `pte2page(*ptep)` 记下旧页 `old`；否则令 `old = NULL`。当 `old != page` 时，调用 `page_ref_inc(page)` 为新映射增加一个引用。若 `old == page`，说明此次操作只需更新权限。
3. **写入映射并刷新翻译。** 执行 `*ptep = pte_create(page2ppn(page), perm)`，用目标页号和本次传入的权限重新构造页表项。随后调用 `tlb_invalidate(pgdir, la)`。即使物理页相同，这一步仍然重要，例如撤销写权限后，CPU 需要丢弃缓存的旧权限。
4. **释放旧引用。** 若 `old` 存在且与 `page` 不同，调用 `page_ref_dec(old)`；计数降到零时才调用 `free_page(old)`。完成后返回 `0`。将回收放在最后，可以保证旧物理页重新进入分配器前，旧映射已经撤销。

##### `page_remove()` 的实现步骤

1. **只查询现有映射。** 调用 `get_page(pgdir, la, &ptep)`，同时取得物理页和末级页表项。其内部使用 `get_pte(pgdir, la, 0)`，查询过程不会分配页表。若中间页表缺失或末级页表项无效，直接返回。
2. **撤销映射。** 将 `*ptep` 清零，再调用 `tlb_invalidate(pgdir, la)`，使 CPU 丢弃该地址的旧翻译。
3. **减少物理页引用。** 调用 `page_ref_dec(page)`，仅在结果为零时释放物理页。因此，若两个地址都映射到 `p1`，删除第一个地址只会让计数从 `2` 降到 `1`，另一个地址仍能访问 `p1`；再次删除第一个地址时，查询已经找不到有效映射，计数仍为 `1`。这也就是删除操作的幂等性。

## [SPECIFICATION]

### `page_insert`

**Pre-Condition**：`pgdir` 指向有效页表根，`page` 指向已分配、可建立映射的受管物理页，`perm` 为调用者要求的页表标志。`la` 可以带有页内偏移，操作对象是其所在的虚拟页。

**Post-Condition**：成功返回 `0`。目标叶子项有效，指向 `page`，权限按本次 `perm` 设置；相关物理页的引用计数反映映射的实际增减。内存不足时返回 `-E_NO_MEM`，原有映射、引用计数和空闲页数量保持调用前的状态。

- **Case 1 · 原地址未映射**：建立映射，目标物理页的引用计数增加一次。若同一物理页已映射到其他地址，那些映射继续有效。
- **Case 2 · 原地址已映射到 `page`**：更新权限，清除旧映射中本次未请求的权限位。该物理页的引用计数保持不变，包括它仅有这一个引用的情形。
- **Case 3 · 原地址已映射到另一物理页**：将映射替换为目标页及本次权限。目标页增加一个引用，旧页减少一个引用。旧页引用归零时回收，仍有引用时保留。
- **Case 4 · 中间级页表分配失败**：撤销本次调用已经挂接的临时页表，归还对应页表页，保留调用前已存在的页表结构。目标地址不留下半完成映射，目标物理页不增加引用。

**Requirements**：新叶子项写入后，使 `la` 对应的 TLB 条目失效，包括仅更新同页权限的情形。若旧物理页需要回收，应先使旧翻译失效，再让物理页进入空闲集合。失败回滚涉及已挂接的中间级页表时，同样应在回收该页表页前完成必要的失效处理。

### `page_remove`

**Pre-Condition**：`pgdir` 指向有效页表根。`la` 可以带有页内偏移，其所在虚拟页可以已映射，也可以未映射。

**Post-Condition**：返回后，`la` 所在虚拟页无有效映射。其他虚拟页的映射保持原状。对同一地址重复调用不会重复减少引用或回收页面。

- **Case 1 · 存在有效映射**：清空目标叶子项，使该地址的 TLB 条目失效，并将原物理页的引用计数减少一次。计数归零时回收物理页，仍有引用时保留。已有中间级页表继续保留。
- **Case 2 · 不存在有效映射**：无论缺少中间级页表，还是已有叶子槽位但其有效位未置位，均直接返回。查找过程不分配页表页，不改变任何引用计数，也不回收页面。

#### 迭代过程

这两个函数的实现经历了三个阶段：先理清映射与引用计数的关系，再处理分配失败和重复删除等边界情况，最后从单独测试推进到完整内核验证。

1. **确定建立、替换和删除映射的规则。** `page_insert()` 先通过 `get_pte(pgdir, la, 1)` 定位末级页表项，再根据旧映射决定如何更新引用计数。原地址未映射时，目标页引用加一；原地址指向另一物理页时，新页引用加一，旧页引用减一；原地址已经指向目标页时，只更新权限，引用计数保持不变。`page_remove()` 则通过 `get_page()` 查询现有映射，只有找到有效映射才清除页表项并减少引用。

2. **补齐失败回滚，并确定旧页的回收时机。** 检查 `get_pte()` 的实现时发现，Sv39 页表遍历可能连续分配两张中间页表页。如果第一张分配成功、第二张失败，仅返回 `-E_NO_MEM` 会留下刚挂到根表上的空页表。因此 `page_insert()` 在调用前保存原根表项，必要时恢复它并回收新分配的页表页。对于成功的替换和删除，两个函数都先更新页表项，再使对应的 TLB 翻译失效，最后才释放引用计数归零的旧页。这样也保证了重复调用 `page_remove()` 时不会再次扣减引用。

3. **先单独验证，再验证完整启动路径。** 最初 Lab2、Lab3 的前置代码尚未补齐，因此先对 `pmm.c` 做 RISC-V 交叉编译，再用宿主模拟测试运行课程 PMM 断言，并额外验证两处分配失败时的回滚。补齐前置代码后，又在 QEMU 中运行完整内核，验证真实页表下的映射访问。`check_boot_pgdir()` 将同一物理页映射到两个虚拟地址，通过其中一个地址写入字符串，再从另一个地址读出相同内容。

#### 最终结果

`page_insert()` 能正确完成首次映射、同页权限更新和异页替换，成功返回 `0`，中间页表分配失败时回滚并返回 `-E_NO_MEM`。`page_remove()` 能安全撤销映射，保留仍被其他地址引用的物理页，对已删除或从未映射的地址可重复调用。

### 功能模块二：中断与异常处理功能

**负责人：** 

#### 模块功能描述

**需要实现的 C 语言接口：**

```c
// kern/trap/trap.c
void interrupt_handler(struct trapframe *tf);
void exception_handler(struct trapframe *tf);
```

**与之衔接的已有接口和状态：**

```c
void print_trapframe(struct trapframe *tf);
void clock_set_next_event(void);
extern volatile size_t ticks;
void sbi_shutdown(void);
#define TICK_NUM 100
static void print_ticks();
```

**功能说明：**

模块一负责把现场交给 `trap()` 并在处理结束后恢复执行，本模块决定“本次 Trap 应该如何处理”。已有 `trap_dispatch()` 根据 `cause` 最高位分发：最高位为 1 时调用 `interrupt_handler()`，否则调用 `exception_handler()`。两个函数使用同一份 Trap frame，处理结束后回到已有的统一返回路径。

时钟中断需要预约下一次事件、增加计数、周期输出，并在累计输出达到规定次数后关机；其他已知中断输出类别提示，未知中断输出原因编号和完整 Trap frame。非法指令和断点异常需要输出发生地址并推进 `epc`，避免返回后重复触发；其他异常保留现场并打印，作为诊断兜底。

#### 关键状态和实现步骤

**1. 区分中断类型位与原因编号**

RV64 的 `cause` 最高位是中断标志，不能直接把带标志的完整值与 `IRQ_S_TIMER` 等编号比较。本实现只在局部变量中清除该位：

```c
uintptr_t cause = tf->cause &
    ~((uintptr_t)1 << (sizeof(uintptr_t) * 8 - 1));
```

使用掩码不会改变 `tf->cause`，也兼容课程测试直接传入没有最高位标志的 `15`。如果使用异或去位，未置位输入会被错误地加上最高位；本次直接调用测试同时检查 `15` 和带最高位的 `15`，两者均输出 `Unknown interrupt: cause 15`。

**2. S 模式时钟中断：重设事件、计数、输出和关机**

时钟分支的核心实现为：

```c
case IRQ_S_TIMER:
    clock_set_next_event();
    ticks++;
    if (ticks % TICK_NUM == 0) {
        print_ticks();
        if (ticks / TICK_NUM >= SHUTDOWN_AFTER) {
            sbi_shutdown();
        }
    }
    break;
```

`clock_init()` 只预约第一次时钟事件。SBI 的定时接口每次设置一个目标时刻，因此每次中断都必须调用 `clock_set_next_event()`；只增加 `ticks` 会使后续时钟事件无法持续发生。`ticks` 在 `clock.c` 中声明为 `volatile size_t`，每次 S 时钟中断恰好加 1。

`TICK_NUM` 是每次统计间隔，`SHUTDOWN_AFTER` 是累计输出次数，两者含义不同。框架未提供后者，本模块在填空区域使用 `#ifndef SHUTDOWN_AFTER` 定义默认值 10，允许通过编译参数覆盖。默认状态变化为：

| 增加后的 ticks | 本次统计输出 | 累计输出次数 | 是否调用关机接口 |
|----------------|--------------|--------------|------------------|
| 1～99 | 无 | 0 | 否 |
| 100 | `100 ticks` | 1 | 否 |
| 200 | `100 ticks` | 2 | 否，课程持续时钟用例可完成 |
| 1000 | `100 ticks` | 10 | 是 |

输出复用已有 `print_ticks()`，没有改成累计数值，也没有改变其 `DEBUG_GRADE` 条件行为。默认运行实测恰好输出 10 行后退出；临时副本用 `-DSHUTDOWN_AFTER=1` 构建时，恰好输出一行后关机。时钟计数为后续调度提供基础，本模块没有实现进程调度。

**3. 其他中断与未知中断的处理**

其余分支按 `riscv.h` 中现有的软件、定时器、外部、协处理器和主机中断常量输出类别提示。例如 S 软件中断输出 `Supervisor software interrupt`。这些分支不更新 `ticks` 或 `epc`。头文件中的类别名称属于框架接口，分类输出本身不表示已实现相应硬件驱动、清除设备中断源或所有来源的实际委托。

无法识别的编号先输出 `Unknown interrupt: cause N`，再调用 `print_trapframe(tf)`。清除类型位只影响局部编号，诊断仍使用原始帧。中断处理函数没有修改保存的任何寄存器或返回地址，因此异步中断结束后继续被打断的执行流。

**4. 非法指令和断点：先输出原地址，再按指令长度推进 epc**

`exception_handler()` 根据原始异常原因分类：

| 异常原因 | 输出内容 | 返回位置处理 |
|----------|----------|--------------|
| `CAUSE_ILLEGAL_INSTRUCTION` | `Illegal instruction at 0x...` | 按该指令的 2/4 字节长度推进 |
| `CAUSE_BREAKPOINT` | `Breakpoint at 0x...` | 按该指令的 2/4 字节长度推进 |
| 其他异常 | `print_trapframe(tf)` | 保留原 epc，直接返回 |

地址输出使用 `%p`，保留 RV64 地址宽度。两个要求跳过的分支共用以下长度判断：

```c
uint16_t instruction = *(const uint16_t *)tf->epc;
tf->epc += (instruction & 0x3) == 0x3 ? 4 : 2;
```

RISC-V 的 16 位压缩指令低两位不为 `11`；在本实验要求处理的 16/32 位集合内，低两位为 `11` 对应 32 位指令。因此不能把所有异常固定推进 4 字节，也不能简单规定“断点加 2、非法指令加 4”。`c.ebreak` 为 2 字节，`ebreak` 为 4 字节，两种长度的非法指令也分别需要处理。

这里只读取首个 16 位半字，允许指令位于仅按 2 字节对齐的地址。前提是已知异常的 `epc` 可读取，且待跳过的指令为 16 或 32 位；本模块没有实现 48 位及更长指令解码。其他异常分支在读取指令之前就返回，不会擅自解引用可能无效的地址。兜底打印也没有解决原异常，返回到未修复的指令仍可能再次触发 Trap。

**5. 与统一返回机制配合**

两个函数均不直接写硬件 `sepc`，也不执行 `sret`。异常分支修改的是帧中的 `tf->epc`，随后模块一的 `RESTORE_ALL` 将其恢复到 `sepc`；中断分支保留 `epc`。其余通用寄存器和状态字段保持不变，使“事件处理决定返回位置，统一恢复路径执行返回”的职责关系一致。

## 六、实验总结与收获

### 对操作系统的理解

**1. 本实验的重要知识点及其与 OS 原理的对应关系**

| 知识点 | OS 原理中的含义 | 本实验中的对应实现及区别 |
|--------|-----------------|--------------------------|
| 中断与异常 | 中断通常由外部事件异步触发，异常由当前指令同步引起；二者都能使处理器转入系统的处理流程。 | 二者共用 `__alltraps` 和 `trap()`，再根据 `cause` 分发。时钟中断和非法指令、断点异常具有不同的处理与返回要求，不能统一理解为跳过一条指令。 |
| 特权级与 Trap 入口 | 操作系统通过受控入口处理低权限软件或硬件事件，权限转换受体系结构规则约束。 | OpenSBI 运行在 M 模式，内核运行在 S 模式；对委托给 S 模式的 Trap，CPU 使用 `stvec` 指定的入口。发生 Trap 不一定改变权限级，S 模式也可以进入 S 模式处理程序。 |
| 上下文与 Trap frame | 上下文是继续执行所需的处理器状态，现场保存使事件处理不会无故破坏原程序。 | `SAVE_ALL` 将通用寄存器和 CSR 快照写入栈上的 `struct trapframe`，`RESTORE_ALL` 按对应布局恢复。Trap frame 是一次 Trap 的现场记录，不是 PCB，也不代表已经切换进程。 |
| 硬件与软件的分工 | 硬件负责必要的 Trap 入口状态更新，操作系统负责进一步保存现场和执行处理策略。 | 硬件记录 `sepc`、`scause` 并更新相关状态，汇编再保存通用寄存器和 CSR 快照。不是硬件自动将全部寄存器压栈，也不是保存两份完整上下文。 |
| ABI 与汇编调用 C | ABI 规定函数参数、返回地址、寄存器保存责任和栈对齐，保证不同代码正确调用。 | `__alltraps` 用 `a0` 传递帧地址，调用 `trap()`。普通函数调用约定不能替代任意位置发生 Trap 时的现场保存，但进入 C 函数时仍要遵守 ABI。 |
| 异常恢复与返回位置 | 异常处理必须决定重试、跳过或终止等策略，不同异常不能采用同一种恢复方式。 | 本实验对非法指令和断点按要求更新帧内 `epc`，恢复代码使用更新后的值；`sret` 根据返回状态恢复执行，不等同于普通 `ret`。其他异常的兜底打印也不代表已经具备通用恢复能力。 |
| 时钟中断与周期事件 | 操作系统利用定时事件维护时间和执行周期工作，调度是其可能支持的上层功能。 | OpenSBI 的定时器接口设置目标时刻，每次时钟中断中重新预约下一次事件，更新计数并定期输出。本实验处理时钟事件，没有实现进程轮转调度。 |
| 临界区与原子性 | 相互关联的数据修改需要避免其他执行流观察到不一致的中间状态。 | 物理页分配接口保存原中断状态、关闭中断并在结束后恢复。它保护当前 CPU 上相应中断造成的干扰，不等于多核互斥，也不表示同步异常不会发生。 |

**2. OS 原理中重要，但本实验没有对应实现的知识点**

- **完整进程管理与调度。** 本实验没有建立进程 PCB、就绪队列和时间片轮转算法，也没有实现不同进程之间的上下文切换。
- **用户进程和系统调用。** 完整系统还需要用户地址空间、用户栈与内核栈切换、系统调用分发和参数检查。本次必做内容基于现有可用内核栈，没有完成这些用户进程机制。
- **按需分页和页面置换。** 本实验复用物理内存及启动映射基础，没有实现缺页分配、页面换入换出或完整的虚拟内存管理。
- **多核同步和复杂中断管理。** 多核共享数据还需要锁、原子指令和跨核协调；中断嵌套、优先级与复杂设备中断也需要进一步设计。
- **扩展寄存器现场。** 当前 Trap frame 保存整数寄存器及相关 CSR，没有覆盖浮点、向量等扩展上下文。

### AI 协作开发的经验

**首先，要把真实接口和布局整理清楚。** 我们以现有结构体、宏和保存逻辑作为 [RELY]，在 [GUARANTEE] 中列出必须完成的接口，避免 AI 自行假设字段偏移或修改框架。特别是旧 `sp` 的保存位置、帧大小、参数传递方式和函数签名，必须与工程一致。

**其次，行为规格要覆盖完整的状态变化。** 模块一关注恢复前后的寄存器、帧基址和返回状态；模块二关注原因分类、下一次时钟事件、计数以及异常处理后的 `epc`。用 Pre-Condition、Post-Condition、Case 和 Requirements 说明这些约束，比只要求“补全函数”更容易检查各模块能否配合。

**再次，要区分生成代码、依赖适配和实际验证。** Lab2 代码迁移时出现的宏名差异说明，旧实现也需要根据当前框架核对，不能直接覆盖整个文件。对生成结果既要检查编译，也要检查寄存器恢复、返回位置和持续事件处理；某一个独立测试通过不能代替整套课程测试。

**最后，团队协作需要明确修改边界和共同接口。** 模块一负责现场管理和汇编到 C 的衔接，模块二负责具体事件处理，双方通过同一份 Trap frame 连接。集成时重点核对返回状态和调用约定；报告中的问题、修正和测试结果以实际过程及终端截图为依据，不能用预期输出替代真实结果。
